# P1 features: Rust core + SwiftUI app

**Spec:** "xrest — Product Brief" doc, tab "Feature specs" (https://claude.ai/artifact/DGjuqzPjXEZ4tnzCZLBefe),
specs F1, F2, G2, G3, H1, I1. Requirements are copied into each task; the task text is binding.
A3, B3 and G1 are already shipped. Follows the P0 plan (2026-10-22-p0-features.md), whose
Global constraints apply unchanged; read them there too.

## Global constraints (every task)

  commit `.impeccable/`, `PRODUCT.md`, or `.superpowers/`.
- Core/app boundary from `docs/architecture.md`: cross-platform behavior in `xrest-core`; `xrest-ffi`
  is a thin mirror; the app owns UI only.
- Strict TDD: failing test first, run it, watch it fail, implement. Implementers paste RED excerpts.
- Environment: `export PATH=/etc/profiles/per-user/ak/bin:$PATH` before cargo/rustup.

- After any `xrest-ffi` API change: `macos/scripts/generate-bindings.sh`, commit the regenerated
  `macos/XRest/Bindings/xrest_ffi.swift`, and `--check` must pass.
- macOS gate (repo root): `macos/scripts/build-xcframework.sh --debug && (cd macos && xcodegen) && xcodebuild -project macos/XRest.xcodeproj -scheme XRest -configuration Debug -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO test`
- Keep `docs/architecture.md` accurate (on-disk format, FFI API, Deferred list).
- Never write secret values to disk, logs, history, exports or git; mask with `••••••` or keep the
  `{{secret.KEY}}` placeholder.
- Commit per task, conventional message ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`

## Rulings fixed by this plan

- Git (F2) shells out to the system `git` binary (`std::process::Command`, no shell, args as a
  vector) so credentials come from the user's git/SSH setup; no libgit2.
- Auto-commit vs manual mode (F2.4) is per user: `.xrest/state.yaml` key `gitMode: auto|manual`,
  default `manual` (nothing commits behind the user's back until they opt in).
- Endpoint revisions (F1) stay in gitignored `.xrest/versions/` (current behavior; brief open question).
- History (H1) is a SQLite database (`rusqlite` with the `bundled` feature) at a path the app passes
  in (macOS: `~/Library/Application Support/XRest/history.sqlite`); never inside a workspace.
  Response bodies are capped at 1 MiB per entry (`truncated: true` beyond).
- OpenAPI import (G2) walks `serde_json::Value` (YAML via serde_yaml_ng) for both Swagger 2 and
  OpenAPI 3; no OpenAPI crate.

## Task 1: Core — endpoint revisions: restore and diff (F1)

Requirements:
1. `Workspace::restore_endpoint_version(id, version) -> Endpoint`: writes that version's config as
   the endpoint's current request through the normal update path, so it becomes a NEW version
   (MAX+1); history is never rewritten. Unknown version → `NotFound`.
2. `Workspace::diff_versions(id, from, to) -> Vec<FieldChange>` (and a pure
   `diff_configs(a, b)`), where `FieldChange { field, change: added|removed|changed, before:
   Option<String>, after: Option<String> }` covering method, url, authenticated, each param /
   path param / header by name (added, removed, value or enabled changed), body (type and content,
   compared as text), options keys, and preflight fields. Ordering is stable (field order as listed).
3. `set_max_versions(n)` exposed through FFI (clamped 5–50 as today).
4. FFI: `restore_endpoint_version`, `diff_versions`, `set_max_versions`, `FieldChange` record.
   Regenerate bindings, update docs.

Tests: restore of v3 after 10 edits yields v11 equal to v3's config; maxVersions 5 drops v1 on the
6th save (existing behaviour, keep a test); diff table covering each field kind; diff of identical
configs is empty; unknown version → NotFound.

## Task 2: Core — git integration via the git CLI (F2)

Requirements:
1. `git::status(root) -> GitStatus { is_repo, branch, remote_url, uncommitted: Vec<GitFileStatus
   { path, status }>, ahead, behind, last_sync: Option<u64> }` from `git status --porcelain=v2
   --branch` and `git remote get-url origin`. `last_sync` = unix time of the last successful
   pull/push/sync, stored in `.xrest/state.yaml`.
2. Actions: `init(remote: Option<String>)`, `commit(message) -> Option<String sha>` (None when
   nothing to commit), `pull()`, `push()`, `sync()` (pull then push). All run with `-C <root>`,
   `GIT_TERMINAL_PROMPT=0`, no shell; stderr is surfaced in a new `Error::Git(String)` (FFI
   `XRestError.Git`). Missing git binary → `Error::Git("git not found")`.
3. Staging only ever adds tracked workspace content: `service.yaml`, `environments.yaml`,
   `endpoints/`, `.gitignore`. `scratchpad/` and `.xrest/` are never staged even if `.gitignore`
   was edited.
4. `gitMode` per user in `.xrest/state.yaml` (`auto|manual`, default manual), get/set API. In auto
   mode every successful save of an endpoint, the environments or service settings creates exactly
   one commit touching only the saved file(s), message e.g. `Update endpoint: List pets`,
   `Update environments`, `Update service settings`, `Create endpoint: …`, `Delete endpoint: …`.
   A failed auto-commit never fails the save; it is returned as a warning on the workspace
   (`warnings()`).
5. Pull with conflicts: never auto-resolve; abort the merge (`git merge --abort`) so files on disk
   are unchanged, and return `Error::Git` listing the conflicting paths. After any successful
   pull/sync the workspace reloads from disk (new endpoints appear).
6. FFI: `git_status`, `git_init`, `git_commit`, `git_pull`, `git_push`, `git_sync`, `git_mode`,
   `set_git_mode`, `reload`. Long-running ones are async or run off the lock; never hold the
   workspace lock while git runs. Regenerate bindings, docs.

Tests (integration, temp dirs, real `git`, a local bare repo as remote, `user.name/email` set via
`-c` or env in the test): status on non-repo and repo; init with remote; commit only tracked
files (scratch file exists but is not committed); auto-commit creates one commit per save touching
one file; manual mode creates none; pull brings a teammate's new endpoint (clone, add, push, then
pull in the first) and reload shows it; conflicting pull leaves files unchanged and lists paths;
push/ahead/behind counts.

## Task 3: Core — OpenAPI / Swagger import (G2)

Requirements:
1. `swagger::parse(content) -> ImportedSpec { title, base_url: Option<String>, endpoints:
   Vec<ImportedEndpoint> }` accepting OpenAPI 3.x and Swagger 2.0, JSON or YAML. Swagger 2 base URL
   = `schemes[0]://host basePath`; OpenAPI 3 = `servers[0].url` (server variables substituted with
   their defaults).
2. One endpoint per path × method (GET, PUT, POST, DELETE, OPTIONS, HEAD, PATCH), name = summary,
   else operationId, else `METHOD path`. URL = `{{BASE_URL}}<path>` with `{param}` tokens kept
   (they are path params; add a `pathParams` row per path parameter, value = schema default or "").
   Query and header parameters → params / headers (value = default or example or ""), including
   path-item-level parameters and `$ref` to `#/components/parameters` / `#/parameters`.
   Request body: first `application/json` example (or schema example) → typed `json` body;
   `application/x-www-form-urlencoded` → `form` fields from schema properties.
3. `create_workspace_from_openapi(path, name, content)`: new workspace, DEV/STAGE/PROD with
   `BASE_URL` (PROD unsafe; spec has no servers → `https://api.example.com` placeholder + warning),
   all endpoints saved at version 1.
4. `merge_openapi(content) -> ImportSummary { added, skipped }` into an open workspace: matches by
   method + path (URL after `{{BASE_URL}}`); adds new operations; never modifies existing
   endpoints.
5. `fetch_text(url)` async helper in FFI for importing from a URL (http/https only, 10 MiB cap).
6. FFI mirrors, bindings, docs (remove swagger from Deferred).

Tests: fixtures for Petstore v2 (JSON) and v3 (YAML) under `core/xrest-core/tests/fixtures/`
(write small but realistic ones yourself); name fallback order; path/query/header params incl.
refs; json body example; form body; server variables; no servers → placeholder + warning; merge
adds only new ops and leaves an edited endpoint untouched; invalid content → InvalidInput.

## Task 4: Core — code export (G3)

Requirements:
1. `export_code(spec, language) -> String` for `curl`, `axios` (Node), `java` (java.net.http
   HttpClient), `kotlin` (OkHttp), using the request resolved for the selected environment:
   variables, path params, query params, service auth and options applied; preflight is not run
   (its header is emitted as a placeholder `<preflight token>`).
2. Secrets: by default every resolved secret value is replaced by its `{{secret.KEY}}` placeholder
   (in headers, URL, body, auth). `include_secrets: true` emits real values (explicit opt-in).
3. Bodies: json/raw/form/multipart (file fields as `@path` in curl, file reads in others)/binary.
4. Exported curl must round-trip: `import_curl(export_code(spec, curl))` yields the same method,
   URL, headers, params-in-URL and body as the resolved spec (auth header included as a header).
5. Shell-safe quoting in curl (single quotes, embedded `'` escaped); language string escaping in
   the others.
6. FFI `export_code(spec, language, include_secrets)`, bindings, docs.

Tests: per language golden snapshots for a GET with params+headers and a POST json; secret
masked by default and present with opt-in; curl round-trip table (json, form, multipart, quotes in
values, unicode); unsafe environment does not matter (export does no I/O).

## Task 5: Core — execution history (H1)

Requirements:
1. `history::SqliteHistory::open(path)` (creates schema, WAL mode). Entry fields: id, created_at
   (unix ms), service_id, service_name, endpoint_id (optional), environment, method, url (final),
   request_headers, request_body, status (optional), status_text, response_headers,
   response_body, body_is_base64, truncated, time_ms, size_bytes, error (optional).
2. Every send (success, non-2xx, transport error; not a policy refusal) records an entry when a
   history is attached: `XRestWorkspace.set_history(history)`. Before storing: drop
   `Authorization`, `Proxy-Authorization`, `Cookie`, `Set-Cookie` header values (keep the name,
   value `••••••`), and replace every resolved secret value occurring anywhere in url, headers or
   bodies with `••••••`. Bodies over 1 MiB are truncated with `truncated = true`.
3. Query API on a separate FFI object `XRestHistory`: `open(path)`, `list(filter, limit, offset)`
   newest first with `HistoryFilter { service_id, endpoint_id, method, status_class (2,3,4,5 or
   0 = error) }`, `get(id)`, `clear()`, `count(filter)`. Listing returns summaries (no bodies);
   `get` returns the full entry.
4. Recording never fails a send (errors become a warning).
5. `docs/architecture.md`: document schema + masking; remove history from Deferred.

Tests: record via a wiremock send (bearer secret in header and secret in query → masked in stored
url/headers); non-2xx and transport errors recorded; ConfirmationRequired not recorded; filters
and paging; 10,000 inserted entries → first page of 50 in < 200 ms (assert with a generous margin,
release-independent: measure and assert < 200 ms in debug if feasible, else document); clear;
body truncation at 1 MiB + 1.

## Task 6: macOS — versions panel with diff and restore (F1)

Requirements: in the request detail, a "History" (versions) panel for endpoints listing versions
newest first (version, time, short summary of changed fields from `diffVersions`), selecting one
shows the field-level diff against its predecessor (added green, removed red, changed before→after),
"Restore this version" asks to confirm then calls `restoreEndpointVersion` and reloads the draft.
A setting for max versions (5–50) goes in Preferences (Task 10) — here only wire
`setMaxVersions` from a stored default. Pure view-model logic (summaries, grouping) unit tested.

## Task 7: macOS — Git panel (F2)

Requirements: the "Git" rail item opens a panel: not-a-repo state with "Initialize" (+ optional
remote URL); repo state shows branch, remote, ahead/behind, last sync, uncommitted files list;
buttons Commit (message field, default generated), Pull, Push, Sync with progress and error text
(stderr from `XRestError.Git`); an "Auto-commit saves" toggle bound to `gitMode`. A badge on the
rail icon when there are uncommitted or unpushed changes (refresh on panel open, after saves and
after git actions; no polling faster than every 30 s). After pull/sync the model reloads endpoints
and environments. Logic (badge state, default commit message, status formatting) unit tested.

## Task 8: macOS — OpenAPI import and code export UI (G2, G3)

## Task 9: macOS — History panel (H1)

Requirements: the "History" rail item opens a panel backed by `XRestHistory` at
`~/Library/Application Support/XRest/history.sqlite` (attached to every workspace on open):
list newest first (method, URL, status with tone colour, time, size, environment), paged (load
more), filters for service, endpoint, method, status class, a Clear button with confirmation.
Selecting an entry shows request/response detail (headers, body using the Task 7 P0 response
viewer). "Open as scratch request" creates a scratch request from the entry (method, URL, headers
minus masked ones, body) — sending it goes through the normal guarded send. Logic unit tested.

## Task 10: macOS — preferences and session restore (I1)

Requirements:
1. Settings window (⌘,): appearance Light/Dark/System, zoom level (UI scale for editors), default
   HTTP options (timeout, follow redirects, verify TLS, proxy) applied via a new FFI
   `set_http_options` (add to core FFI in this task, it exists in core), default max versions
   applied via `setMaxVersions`. Stored in UserDefaults, never in a workspace.
2. Session restore: on launch reopen the windows of the workspaces open at quit and, per
   workspace, the selected request and any unsaved drafts (drafts stored in Application Support,
   never in the workspace; they may contain typed secrets only as `{{secret.KEY}}` — store drafts
   exactly as typed but warn in code comments that plain secrets typed into a draft are persisted
   locally; acceptable).
3. Acceptance: quit with an unsaved draft and relaunch restores the draft (unit test the
   persistence layer with an injectable directory).
