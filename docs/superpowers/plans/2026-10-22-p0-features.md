## Task 1: Core — path params (B1) and format version 2

Requirements:
1. `RequestSpec`, `Endpoint`, `ScratchRequest` and version snapshots gain `pathParams: Vec<NameValue>`
   (YAML key `pathParams`, omitted when empty, default empty on read).
2. During resolve, after variable interpolation, each `{name}` token in the URL **path** (never the
   query, never `{{…}}`) is replaced by the enabled path param of that name, its value interpolated
   (variables + secrets) and percent-encoded as a path segment. Tokens with no enabled param stay
   verbatim and are added to `unresolved_variables` as `{name}`.
3. Bump `FORMAT_VERSION` to 2 (an older core would drop `pathParams`). Format 0 and 1 workspaces
   still open and are stamped 2 on first save, exactly as 0→1 works today.
4. Mirror `path_params` in `xrest-ffi` records; regenerate bindings.
5. cURL import: no change (curl has no path params).
6. Update `docs/architecture.md` (format table, endpoint example, resolution steps).

Tests: resolve unit tests (substitution, encoding of `/` and space, interpolated value, disabled
param, missing param reported, `{{VAR}}` untouched, query `{x}` untouched); storage round-trip;
format-1 fixture opens and saves as 2; format-3 workspace refused.

## Task 2: Core — preflight absolute expiry and Test Preflight (D2)

Requirements:
1. With `cacheDuration: derived`, `cacheDurationUnit` additionally accepts `epoch` (seconds since
   1970), `epoch_ms`, and `iso8601`; the value at `cacheDurationKey` is then an absolute expiry
   time. Numbers may arrive as JSON numbers or numeric strings. An expiry in the past or
   unparsable falls back to the 5-minute default TTL. (Parity with legacy `preflight.go`
   `ExpiryType`.)
2. New core API `Workspace::test_preflight(preflight: Option<Preflight>, confirmed: bool)` using the
   service preflight when `None`. Applies the unsafe policy exactly like send
   (`ConfirmationRequired` before any I/O), uses the selected environment's variables and
   secrets, never reads or writes the token cache, and returns `PreflightTestResult { method, url,
   request_headers, request_body, status: Option<u16>, response_headers, response_body,
   token: Option<String>, error: Option<String>, time_ms }`. A token-extraction failure is a
   result with `error` set, not an `Err`.
3. Export through FFI as async `test_preflight(preflight: Option<Preflight>, confirmed: bool)`;
   regenerate bindings; document in `docs/architecture.md`.

Tests: expiry parsing for each unit incl. string numbers, past and garbage values; test_preflight
against the existing local test server pattern in `core/xrest-core/tests/send.rs`: success with
token, bad tokenKey → `error` names the path, unsafe env without confirm → `ConfirmationRequired`
and no request reaches the server, cache untouched (a following send still fetches a token).

## Task 3: Core — foreign secret provider (E2)

Requirements:
1. In `xrest-ffi`, a foreign-implementable callback trait
   `#[uniffi::export(with_foreign)] pub trait SecretProvider: Send + Sync { fn get(&self, key: String) -> Option<String>; }`
   and `XRestWorkspace::set_secret_provider(provider: Arc<dyn SecretProvider>)`.
2. Lookup order: the provider, then the in-memory store fed by `set_secret` (kept for tests).
   Missing keys still fail the send with `MissingSecrets(keys)` before any request.
3. Core-side: the adapter implements `xrest_core::secrets::SecretStore`; no Keychain code in Rust.
4. New FFI `secret_keys_in_use() -> Vec<String>`: every distinct `{{secret.KEY}}` and `secretKey`
   referenced by the service, environments, endpoints and scratch requests (for the app's
   "you still need these secrets" list).
5. Regenerate bindings; update `docs/architecture.md` (remove the Keychain TODO from Deferred).

Tests: Rust test with a Rust-side impl of the trait proving provider-first order and the fallback;
missing secret error lists exactly the missing keys; secret_keys_in_use over a fixture.

## Task 4: Core — write APIs for environments and service settings; interpolation preview (C1, C2, D1)

Requirements:
1. `save_environments(envs: Vec<EnvironmentConfig>)`: validates names (trimmed, non-empty, unique,
   else `InvalidInput`), writes `environments.yaml` atomically, stamps the format version like other
   saves, keeps the selection if the name still exists, otherwise falls back to the first.
2. `update_service_settings(settings: ServiceSettings)` where `ServiceSettings { name,
   is_authenticated, auth_type, basic_user, basic_pass, bearer_token, api_key_name, api_key_value,
   api_key_location, preflight: Option<Preflight> }`; writes `service.yaml` (preserving `id`,
   `gitUrl`, format version stamping); clears the token cache. `ServiceInfo` exposes the same fields
   so the app can edit them.
3. `preview(text: String) -> InterpolationPreview { resolved, unresolved: Vec<String> }` for the
   selected environment: variables resolved, every secret value replaced by `••••••` (never the
   value), unresolved names listed. Pure, no I/O beyond secret lookup.
4. `variable_names() -> Vec<String>`: enabled variable names of the selected environment (for
   autocomplete).
5. FFI mirrors, regenerated bindings, docs.

Tests: save_environments validation and round-trip; selection fallback; update_service_settings
round-trip leaves endpoints untouched and clears cache; preview masks secrets, reports unresolved.

## Task 5: macOS — test target, Keychain secret store, Secrets screen (E2)

Requirements:
1. Add an `XRestTests` unit-test target in `macos/project.yml` (hosted by the app, `TEST_HOST`),
   included in the shared scheme so `xcodebuild … test` runs it.
2. `KeychainSecretStore` (generic passwords, service name injectable; app uses
   `dev.xrest.secrets`) implementing the generated `SecretProvider` protocol plus `set`, `delete`,
   `keys`. Keychain cannot enumerate cheaply, so keep a names-only index in
   `~/Library/Application Support/XRest/secret-keys.json` (path injectable for tests). Values
   never go in the index, logs, or UserDefaults.
3. `WorkspaceModel` installs the provider on every workspace open.
4. Secrets screen (rail item "Secrets", key icon, plus a menu command): list keys, add (key +
   SecureField value), delete with confirmation, explicit "Reveal" per key that shows the value
   until the sheet closes. Values are write-only otherwise. Show "Needed by this service" from
   `secretKeysInUse()` with missing ones highlighted and an Add action.
5. A `MissingSecrets` send error offers a button that opens the Secrets screen prefilled with the
   first missing key.

Tests (XCTest, unique service name per test, cleaned up): set/get/delete round-trip, index holds
names only, provider returns nil for unknown key, persisted across store instances.

## Task 7: macOS — response viewers, copy/save, cancel, unresolved warning (B4)

Requirements:
1. Testable `ResponseKind` classification from content type and `bodyIsBase64`: json, html, image,
   xml/text, binary.
2. Tabs: Pretty (JSON pretty; HTML rendered in a `WKWebView` with JavaScript disabled and no base
   URL; images via `NSImage`; binary shows a hex dump of the first 64 KiB), Raw, Headers.

8. Status color: 2xx green, 3xx amber, 4xx/5xx red.

Tests (XCTest): ResponseKind table, hex dump formatting, truncation threshold, base64 decode for save.

Tests (XCTest): grid round-trip preserves order, secretKey, enabled; removing a variable removes it
